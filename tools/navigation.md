# tools/ — agent tooling

| Script | What it does | Writes anything? |
|---|---|---|
| `Test-Compile.ps1 -IncludeRuntimeCode` | Compiles **this repo's** `src/Code/*.cs` with PK9's Roslyn against `PK9\Bin`, plus every published file in `PK9\App_RuntimeCode` except our own published copies (incl. `ProjectTask.PMTask.cs`). Prints `COMPILE OK`. `-ExcludeRuntimeFile X` drops another project's file (e.g. `PX_Objects_CR_Contact_extensions` for the T-10 cutover). | No (DLL/rsp in `%TEMP%`) |
| `Test-ModernUI.ps1` | Type-checks `src/FrontendSources/screens/**/*.ts` against PK9's client-controls typings and base screens (PK9's own Node + TypeScript). Prints `TS CHECK OK`. Does not validate HTML. | No (temp tsconfig in `%TEMP%`) |
| `Build-Package.ps1` | Builds `build\ProjectTask.zip` (project.xml + files) from `src\`: Code, Sql, Tables, SiteMap, Automation, PageCustomizations, Pages (ASPX shells), FrontendSources (Modern UI). `-SrcDir` / `-OutFile` to build from another tree. Code item kind (NewGraph/NewDac/NewFile) per file comes from its `$CodeFileType` table: **register every new graph/DAC file there.** Does not import or publish. | `build\` only |
| `Verify-Package.ps1` | Compares a zip (default `build\ProjectTask.zip`) item by item with the live `ProjectTask` project (CompanyID 2) and the `App_RuntimeCode` copies. Prints `PACKAGE MATCHES LIVE` (exit 0) or `PACKAGE DIFFERS FROM LIVE` (exit 1). **`-ExtraProject Contact`** (T-10 merge): compares with live ProjectTask + Contact combined; a live `DAC` item (Data Class editor) counts as matched when exactly one zip code item extends that DAC with the same fields, types and attribute lines and the zip `Table` has the columns. It also checks the code against the file Acumatica generated from the DAC item (`PX_Objects_CR_Contact_extensions.cs`). Until the T-10 cutover is published, plain Verify shows the 5 Contact items as `NOT LIVE` (expected). **Page items:** the root `pageSource` attribute (deflate+base64 snapshot of the page, re-generated by Acumatica on every import) is ignored by default, and a note lists the items where it differed. **`-StrictPageSource`** compares it too. Everything else in a Page item is still exact, incl. `OriginalIndex` and the base-control anchor elements, which Acumatica also re-bases when the base page changed (e.g. after a version upgrade). | No (read-only SQL) |
| `Test-StatusSeed.ps1` | **T-21 seed-diff test.** Parses the `VALUES` rows of `src\Sql\PKProjectStatus.sql` and compares them with the 4 frozen pre-T-22 `PXIntList`s (from `src\Code\Contract.cs` while it has them, else `PK9\App_RuntimeCode\Contract.cs`, else the git history of `src/Code/Contract.cs`; `-ContractFile`) = must be identical; `[0]` checks that `src` puts `PKProjectStatusList("<dept>")` on each field with a seeded department (T-22); and with live `CSAttributeDetail` = equal except the approved D1/D2 deviations. Also ScriptDom syntax parse, read-only bind check of the seed SELECT, and (after publish) the table vs the seed. Prints `SEED TEST PASS` / `SEED TEST FAIL`. | No (read-only SQL; never runs the script) |
| `Test-TemplateDates.ps1` | **T-32 due-date unit test.** Compiles `src\Code\PKTemplateDueDate.cs` + a console harness with PK9's Roslyn into `%TEMP%\PKTemplateDates\` and runs 36 cases (earlier/later/equal month-day, other years, Feb 29, null start/template, realistic 3/15-4/15-5/15 tasks, as-is rule). Static checks: no `using PX` in the rule file, the extension calls `PKTemplateDueDate.GetDueDate`, `ActiveRule` = `-ExpectRule` (default RollForward). Prints `DATE TEST PASS` / `DATE TEST FAIL`. | No (`%TEMP%` only) |
| `Test-PKStatus.ps1` | **T-25 PK Status test.** Static checks (the C# department → status field mapping in `src\Code\PKDepartmentStatus.cs` = the `PKProjectStatusList("<dept>")` fields in `Contract.cs` = the CASE list in `src\Sql\PKProjectStatusBackfill.sql`; column sizes; read-only fields), compiles `PKDepartmentStatus.cs` + harness into `%TEMP%\PKStatusTest\` and runs 16 cases, ScriptDom parse of the backfill (and its dynamic UPDATE), then a read-only PK9 preview (rows the backfill would write = drift after publish, PK Status per department; `-SkipDatabase`). Prints `PK STATUS TEST PASS` / `FAIL`. | No (`%TEMP%`, read-only SQL; never runs the UPDATE) |
| `Get-LiveProject.ps1` | Read-only export of a live project (`-ProjectName`, default ProjectTask) into a src-shaped tree `build\live\src` + `build\live\items.csv`. File bodies come from the PK9 site copies (PK9 keeps uploads in Azure blob storage). Item types it has no folder for (e.g. `DAC`) go to `Other\<Type>\`. Example: `-ProjectName Contact -OutDir build\live-contact`. Re-sync of `src\` (T-90): `-OutDir <repo>\src`, only when asked. | `build\live*\` only |

Order before handing over a package: `Test-Compile.ps1 -IncludeRuntimeCode` → `Test-ModernUI.ps1` → `Build-Package.ps1` → `Verify-Package.ps1` (→ `Test-StatusSeed.ps1` when the status seed or `Contract.cs` lists change; → `Test-TemplateDates.ps1` when `PKTemplateDueDate.cs` / `PKProjectTemplateExt.cs` change)
(until the T-10 cutover is published: `Test-Compile.ps1 -IncludeRuntimeCode -ExcludeRuntimeFile PX_Objects_CR_Contact_extensions` and `Verify-Package.ps1 -ExtraProject Contact`)
(a deliberate change shows as DIFF only on the items you changed; anything else is drift).

`Test-ModernUI.ps1` and `Test-Compile.ps1` are adapted from `..\Acumatica-PK-TimeClock\tools\` — keep in sync if those change.
**Do not use `..\Acumatica-PK-TimeClock\tools\Test-Compile.ps1` for this repo:** it compiles the TimeClock repo's own `src\Code`, so it never sees edits made here
(it is still useful to check that PKTimeClock compiles against what is published).
Other tools live there: `Query-PK9.ps1` (read-only SQL; used by the scripts above), `Inspect-Acumatica.ps1` (reflection).
