## Learnings
- Customization item content is in `CustObject.Content` (XML with a `<CDATA name="Source">` / `CustomScript` body) joined `CustObject.ProjectID = CustProject.ProjID`. A read-only SELECT is enough to re-extract `src/` (filter `CustProject.Name='ProjectTask'`, `CompanyID=2`, Type in Graph/Sql/Table/SiteMapNode). File items (`File#…`, `PerTenantFile#…`) store only a FileID — their bodies are the site files (`CstPublished\Pages_PK`, `FrontendSources\…\customizationScreens\Company\screens`).
- Runtime copies in `App_RuntimeCode` carry other names than the item: PMTask item → `ProjectTask.PMTask.cs`; `PMTask.cs` there is Velixo's.
- `PMTask` and `Contract` code items are `FileType="NewFile"` extensions (`PXCacheExtension`), not DACs; `PMDocumentGathering` / `PMSampleTesting` are `NewDac`; the two `*Maint` are `NewGraph`.
- The Modern UI extensions on the site are named `…_PKProjectInfo` / `…_PKTaskInfo` and belong here; `…_PKTimeClock` ones on the same screens belong to other projects.
- **Packaging (T-00):** `tools\Build-Package.ps1` → `build\ProjectTask.zip`; `tools\Verify-Package.ps1` compares it item by item with live (`CustObject` Type+Name, attributes, bodies with line endings normalized). Code `FileType` (NewFile/NewGraph/NewDac) is kept in the `$CodeFileType` table of Build-Package; new code files default to `NewFile`. Importing a zip **replaces** all items of the project, so anything missing from `src/` is deleted.
- **Uploaded file bodies are not in the PK9 DB:** `UploadFileRevision.Data` is empty and `BlobHandler` points at Azure blob storage (`BlobStorageConfig` = `PXBlobStorageAzureProvider`, account `pricekubeckablobstorage`, same settings as the live tenant). Tools use the site copies instead (`PK9\Pages\PK\`, `…\customizationScreens\Company\screens\`); `UploadFileRevision.Size` is KB rounded up (sanity check).
- Live `CustObject.Content` always has LF: Acumatica parses project.xml as XML, so CRLF inside CDATA becomes LF. Package line endings don't matter.
- `Page` items (`<Page path="~/pages/…" pageSource="…">`) hold a deflate+base64 Classic page source; for PKPM3002/3003 it equals the ASPX shell. They don't affect Modern UI but are part of the project.
- `..\Acumatica-PK-TimeClock\tools\Test-Compile.ps1` compiles **the TimeClock repo's** `src\Code` (it resolves the repo from its own folder) — it never sees this repo's edits. Use **`tools\Test-Compile.ps1 -IncludeRuntimeCode`** here (leaves out our published copies, incl. `ProjectTask.PMTask.cs`).
- The project also exists in CompanyID -100020002 (same 34 items, same hashes) and -100020001 (23 items, older) — snapshot/system rows; tools use CompanyID 2.
- **Contact merge (T-10):** the live `Contact` project had 5 items: `DAC#PX.Objects.CR.Contact` (Data Class editor item; Acumatica generates `App_RuntimeCode\PX_Objects_CR_Contact_extensions.cs` from it), `Table#Contact`, Classic `Page ~/pages/cr/cr302000.aspx`, and 2 `PerTenantFile` (`CR302000_PKMarketing.ts/.html`). - **Status ints are load-bearing (T-20):** 135 GI result columns in 73 GIs show `Usr401kStatus/UsrPGTaxStatus/UsrPGAcctStatus/UsrPGAuditStatus` (text comes from the list attribute); 62 GI conditions in 46 GIs and 6 active business events test the int values; 401k IDs are tied to task codes in GI expressions (`CInt(Left([PMTask.TaskCD],2))`). Never renumber or reuse an ID; never switch these fields to `PXSelector` (GIs would show numbers). Base patterns for a DB-backed list: `PX.Objects.AP.Box1099NumberAttribute` (PXIntList + `PXDatabase.GetSlot`) and `PX.Objects.CR.CROpportunityStagesAttribute` (active + current value only). `PXIntListAttribute` has no `FieldVerifying`.
- STATUS* attributes are used only as lookup tables (0 `CSAttributeGroup`, 0 `CSAnswers`); 6 GIs join `CSAttributeDetail` on them (GI000142/137/143/144, GI993814, GI641674). GI000144 joins `STATUSACCT` on `PMTask.UsrPGTaskStatus` (existing bug).
- **Removing a column from a Table item never drops the DB column (T-11 evidence):** `PMTask.UsrPGAccountingStatus` / `UsrPGTaxStatus` exist in the DB but no `CustObject` Table item in any company declares them; in `PK9\Bin` only `PX.DbServices` (`CmdColumnDrop`, built only by `AcumaticaDbKeeperBase`, the install/upgrade schema keeper) emits `DROP COLUMN`; no `PX.Web.Customization*` assembly does. Retired fields keep their `<Column>` line on purpose (`UsrPGTechStatus`, `UsrPGReleasedFinalDeliverables`).
- Published Automation state lives in `AUScreenFieldState` / `AUScreenConditionState` / `AUScreenConditionLineState` (CompanyID 2, by ScreenID). Use them to check which fields a condition drives before removing it.
- `Page` item `pageSource` (PM301000) is the deflate+base64 **base** ASPX, without `Usr*` fields; field edits only touch the `AddItem` elements. Decode: `[IO.Compression.DeflateStream]` over `[Convert]::FromBase64String(...)`.
- Files from `build\live\src` (Automation, PageCustomizations, `.ts/.html`) are LF; `src\Code` / `src\Tables` are CRLF. git `text=auto` hides this in diffs; compare raw bytes against `build\live\src` to prove a minimal edit.
- GI `GIWhere` rows can be inactive (`IsActive = False`) and still name a field; delete them anyway before removing a DAC field.
- **CSAttributeMaint internals (T-21, IL 26.200):** views `Attributes` (primary), `CurrentAttribute`, `AttributeDetails` (`Where attributeID = Current<CSAttribute.attributeID>`, `OrderBy sortOrder, valueID`). Its `Persist()` rebuilds `CSAttribute.List` from `AttributeDetails` (marks the attribute Updated if the list changed) and invalidates the screen-info cache. `CSAttributeDetail_RowDeleting` / `ValueID_FieldUpdating` block only values in use by `CSAttributeGroup`/`CSAnswers`; `CheckIfSettingsCanBeChanged` checks `AttributeGroups`/`AttributeScreens`. `CSAttributeDetail.Description` is `PXDBLocalizableString(60)`, `SortOrder` is `PXDBShort` (smallint). To sync from code: `CreateInstance<CSAttributeMaint>()`, set `Attributes.Current`, insert/update `AttributeDetails`, `Persist()`.
- **DB-backed `PXIntListAttribute` (T-21):** `_AllowedValues/_AllowedLabels/_NeutralAllowedLabels/_ExclusiveValues/_AttributeLevel` are protected; base `CacheAttached` copies the labels and localizes (set `IsLocalizable = false` for user data); base `FieldSelecting` only builds the state when `_AttributeLevel == Item || e.IsAltered`; `PXIntState.CreateInstance(e.ReturnState, …, values, labels, exclusive, typeof(int), null, labels, null)` replaces the lists on an existing state. Slot: `PXDatabase.GetSlot<T>(key, typeof(Table))` with `T : IPrefetchable, IPXCompanyDependent` (`IPXCompanyDependent` is in **PX.Common**); `ResetSlot<T>(key, tables)`; read with `PXDatabase.SelectMulti<T>(new PXDataField<T.field>()…)`.
- `[PXLocalizable]` needs `using PX.Common;` (CS0246 otherwise).
- **Sync-into-another-table pattern:** wrap `base.Persist()` + the second graph's `Persist()` in one `PXTransactionScope`; read the just-saved rows with `PXDatabase.SelectMulti` inside the scope (no graph/query cache), and reset slots only after `ts.Complete()` so an uncommitted read never lands in a global cache.

- **`PXCache<T>.Insert(object)` verifies on a FRESH row (T-22, IL 26.200):** `Insert` → `FillWithValues(new T(), ref data)` raises `FieldDefaulting` then, for each non-null source value, `OnFieldVerifying(field, freshRow, …)` **before** setting it (so `e.Row`'s value is the default, usually null); a `PXSetPropertyException` is parked in `_PendingExceptions` and `Insert` **throws** it after `RowInserting`. `Update(object)` instead calls `FillWithValues(cachedRow, copy, data)` and verifies on the cached row that still holds the OLD value. Consequence: "reject unless unchanged" rules break inserts of copies (`ProjectEntry.Copy` = `Project.Insert(CreateCopy(source))`, which copies `ContractExt` fields). Exempt copies with `ProjectEntry.IsCopyPaste` (public getter; set only by `Copy`/`CopyProject`) and `PXGraph.IsCopyPasteContext` (field).

- **`PXCache<T>.SetValueExt` does not throw on validation errors (T-32, IL 26.200):** it catches `PXSetPropertyException`, calls `OnExceptionHandling`; `PXUIFieldAttribute.ExceptionHandling` parks the error on the field (Cancel = true, value NOT set) and `SetValueExt` only writes `PXTrace.WriteWarning`. At save, `PXUIFieldAttribute.CommandPreparing` throws `PXOuterException` "… record raised at least one error" for any Error/RowError level. So `try { SetValueExt } catch` does not protect a save: read `PXUIFieldAttribute.GetErrorOnly(cache,row,field)` (Error/RowError only), clear with `SetError(cache,row,field,null)`, re-raise as `SetWarning` (level Warning is skipped by CommandPreparing).
